# TravelAssistantGate

门票客服 Agent 的评测工具:**评测对象是"模型 + 工具 + 世界状态"耦合成的任务系统 —— 不止一个回答,也不止一次执行。**

被测 Agent 会自主规划 —— 选工具、调工具、查知识库、编排多步任务、改写业务
数据。只看"最终答案对不对"远远不够:答案对不代表过程对,更不代表世界真的
被正确地改了。单次执行的质量是整个评测的地基,本工具先把它评透 —— 四维断言:

| 维度 | 断言什么 |
|------|---------|
| **Plan 规划** | 任务拆解是否覆盖关键步骤(工具锚点优先,LLM judge 仅语义兜底) |
| **Tool 工具** | 工具选择三档匹配(exact_seq / set / contains)+ 关键参数逐个 diff + forbidden 一票否决 |
| **Trajectory 过程** | 步数上限、循环检测、缺槽位必须追问、顺序约束、失败后诚实说明 |
| **Outcome 结果** | 答案关键词断言 + **世界状态断言**(SQLite 里退款单金额、状态流转、幂等) |

世界状态断言是核心差异:Agent 说「已退款 288 元」不算数,`refunds` 表里单建了、
金额对、订单状态流转了、幂等没破,才算 —— 验证世界,不验证文字。

## 评测版图

Agent 评测是一套持续的建设,不是一个打分动作。单次执行的四维断言是第一层
地基,完整的版图分层推进:

| 层 | 评什么 | 状态 |
|----|--------|------|
| **执行质量** | 单次执行四维断言(上表) | 当前版本核心 |
| **稳定性** | pass^k 重复执行一致性(写操作/对抗类 k=3);对抗切片:提示注入、越权、诱导绕过、幻觉工具 | 当前版本核心 |
| **效率** | 每次执行的 token 用量、LLM/工具调用次数(轨迹自带 meta,报告输出成本仪表盘) | 当前版本核心 |
| **回归与门禁** | 基线 diff + tolerance + eval-gated CI:轨迹评测退化即红 | 当前版本核心 |
| **会话与记忆** | 多轮上下文延续(「把它退了」的指代消解)、跨轮槽位累积、跨会话记忆一致性与记忆污染对抗 | 路线:被测 Agent 多轮化后 |
| **隔离** | 并发多用户执行互不串扰、同一订单并发申请的幂等、会话间上下文隔离 | 路线:越权单点已在对抗切片,系统性隔离评测待并发执行基建 |
| **检索质量** | 知识库检索命中率与排序(hit@k)、答案对检索证据的忠实度 | 路线 |
| **线上回流** | 线上轨迹采样回灌离线回归集,Good/Bad Case 持续喂养任务集 | 远期 |
| **多 Agent 协作** | 轨迹按 agent_id 切片聚合、任务分配与 Agent 间消息断言、并发写冲突(世界断言不变:终态只有一个) | 远期:被测 Agent 多 Agent 化后 |

## 命名

- 项目全称:**TravelAssistantGate**(旅游助手 Agent 的质量门禁)
- 仓库:`travel-assistant-gate`;包与 CLI 简称:`travelgate`

## 架构

```
travelgate/     评测工具:轨迹 schema / 四维评分器(纯函数)/ 匹配器 / 基线 / 报告 / CLI
sut_agent/      被测 Agent:门票客服(Planner + ReAct 循环 + 8 业务工具 + sqlite 世界)
golden/         任务集(JSONL golden set,git 版本管理)
tests/          平台自测(全离线,Fake 注入)
```

关键设计:**每次执行从种子重建独立 sqlite 世界 + 固定时钟**(2026-10-01)——
退票手续费档位完全确定、并发执行互不污染、行级断言可预期。这是轨迹评测
flakiness 控制的地基。

## 开发

```bash
uv sync                                  # 安装依赖
uv run pytest                            # 全离线单测
uv run ruff check .                      # lint
uv run mypy travelgate sut_agent         # 类型检查
```
